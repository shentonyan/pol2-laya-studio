# PoL2 Laya 训练方案（v2 起）

> 状态：方案草案，2026-09-28。还没有开始执行。
> 本方案吸收了一条组内意见：**训练时 PoL2 数据最多占 10%，其余必须是与 PoL2 无关或只是相关的数据。**
> 所有数字标明来源：「实测」来自本仓库已有的实验；「估计」是推算，执行后要用实测替换。

---

## 0. 一页纸摘要

| 问题 | 答案 |
|---|---|
| 要做什么 | 训练一个 PoL2 判别能力更强、**通用能力不退步**的 Laya 模型 |
| 怎么做 | 用预训练编码器（mmBERT-base），在**混合数据**上做 RLCD 训练。PoL2 按题目数计 ≤ 10%，其余约 90% 是近邻任务、通用理解和 Agent 场景 |
| 分几条路线 | **路线 1**：从官方 `laya-multilingual` 继续训练，先做，成本低。**路线 2**：从 mmBERT 编码器 + 空白决策头重建 Laya，用同一份数据，做对照 |
| 不做什么 | 不从零预训练编码器（5070 或 Spark 上都要一年以上，缩小规模也要数周，而且效果不如现成的 mmBERT） |
| 怎么判断成功 | 考两张卷：PoL2 卷要超过 v1 学生；通用卷不能明显低于官方模型。再用 0/5/10/20/100% 的比例对比实验验证 10% 这条上限 |
| 算力 | 训练在 RTX 5070 上即可，每次约 1–15 小时（估计）。本地老师打标签是最慢的环节，有 DGX Spark 可以用更大的老师 |
| 周期 | 约 4–6 周（估计） |

## 1. 背景与已知事实

### 1.1 Laya 的结构

```
预训练编码器 (mmBERT-base, 约 3 亿参数)  →  决策头 (2 层 Transformer + 打分器, 约 1500 万参数)
```

- 编码器是 JHU 开源的，Laya 作者没有从零训练它。
- 官方 multilingual checkpoint 的配置里记录着 `hours: 4.97, world_size: 1`（见 `distill_data/models_meta/*.rl_agent_config.json`，是从基座继承来的），也就是官方在预训练编码器上用 1 张卡训了约 5 小时。
- 训练方法是 RLCD：以严格适当评分规则（log、spherical、有序题的 RPS）作为奖励做 GRPO 式策略梯度，再加软交叉熵引导，最后按题型拟合温度。本仓库的 `distill/train.py` 已经实现了这套方法。

### 1.2 v1 的结果（2026-09-24，见 `docs/findings/2026-09-24_distill_v1.md`）

- 训练数据 **100% 是 PoL2**：1292 行、3192 道题（其中 381 道做校准），5 个场景。
- 在 5070 上约 2.5 分钟训完 4 个 epoch（**实测**），约合 75 题/秒，这是本方案所有时间估计的基准。
- 优点：概率校准好（ECE 约 0.05），A/B 互换一致率 1.00，归属效应很小。
- 负结果：`syco.sycophantic` 的准确率等于多数类基线 0.787，模型没有学会判断谄媚（训练集正例只有 14 条）。
- **缺口**：没有测过通用能力有没有退步。

### 1.3 为什么 PoL2 最多占 10%

1. **防止灾难性遗忘**：参数是共用的，只在 PoL2 上训练会覆盖掉原有能力。
2. **防止走捷径**：PoL2 文本全部由 gemma4 合成，风格单一，模型容易学到表面特征（比如某些词出现就答"是"），而不是题意。
3. **应对分布外输入**：真实输入比合成样本杂乱得多，见过的文本越多样，越不容易在陌生输入上高置信地答错。

10% 是经验上限，不是定理。第 6.3 节的比例对比实验会检验它。

## 2. 目标与验收标准

| 维度 | 指标 | 验收线 |
|---|---|---|
| PoL2 能力 | 独立裁判卷、构造 gold 卷的准确率 | 高于 v1 学生（0.861 / 0.770） |
| PoL2 难点 | `syco.sycophantic`（构造 gold，300 条全新样本） | **高于多数类基线 0.787** |
| 通用能力 | 通用考卷的宏平均准确率 | 路线 1：比官方 multilingual 最多低 2 个百分点。路线 2：不低于官方 multilingual |
| 校准 | ECE，PoL2 和通用**分开报告** | 两边都 ≤ 0.08 |
| 不变性 | 谄媚归属效应、A/B 互换一致率 | ≤ 0.03，≥ 0.95 |
| 人工核验 | 人工金标集（盲标） | 至少有一份，报告人与人之间的一致率 |

验收线是暂定的，可以在执行第一个实验（E0）之后，根据基线的实际水平调整。

## 3. 数据方案

### 3.1 总配比（按**题目数**计）

| 数据池 | 占比 | 作用 |
|---|---:|---|
| **pol2**：PoL2 五个场景 | **≤ 10%** | 专项能力 |
| **neighbor**：近邻任务 | 约 30% | 与 PoL2 相关但不相同，逼模型学会真正区分语气、态度和诚实 |
| **general**：通用理解 | 约 45% | 保住基本的阅读和分类能力 |
| **agent**：Agent 场景 | 约 15% | 保住 Laya 原本擅长的分诊、护栏和路由 |

额外约束：
- **语言**：中文 ≥ 50%，其余以英文为主。PoL2 文本以中文为主，而近邻任务的公开数据以英文居多，所以需要刻意补中文。
- **题型**：choice / score / noul 三种题型都要有，每种至少占 20%。
- **选项数**：单题选项尽量 ≤ 20。Laya 的 `head_max_len` 在选项太多时会挤压每个选项的 token 预算。

### 3.2 数据来源候选

> 每个数据集使用前都要**逐个核实许可**（有些只允许学术用途），并在 `distill_data/general/SOURCES.md` 里记下来源、版本和许可。下表列的是候选，不是定稿。

**neighbor（近邻任务）**

| 任务 | 中文候选 | 英文候选 | 转成的题型 |
|---|---|---|---|
| 情感 / 评分 | ChnSentiCorp | SST-5、Yelp Review Full | score（几星）、noul（是否正面） |
| 冒犯 / 毒性 | COLD、ToxiCN | Jigsaw Toxic Comments | noul、choice（冒犯类型） |
| 立场检测 | NLPCC 2016 微博立场 | SemEval-2016 Task 6 | choice（支持 / 反对 / 中立） |
| 讽刺 / 反语 | — | SemEval-2018 Task 3 | noul |
| 礼貌程度 | — | Stanford Politeness Corpus | score |
| 事实核查 | — | FEVER | choice（支持 / 反驳 / 信息不足） |
| 操纵性话语 | — | MentalManip（待核实） | noul |
| **反捷径对照题**（自造） | 由本地 LLM 生成 | 同左 | 与 PoL2 同题，但答案相反，见 3.4 |

**general（通用理解）**

| 任务 | 中文候选 | 英文候选 | 转成的题型 |
|---|---|---|---|
| 新闻 / 短文本分类 | THUCNews（仅学术）、TNEWS | AG News | choice |
| 自然语言推理 | OCNLI、CMNLI | XNLI、MNLI | choice（蕴含 / 矛盾 / 中立） |
| 是非阅读理解 | — | BoolQ | noul |
| 多选阅读理解 | C3 | — | choice |
| 句子等价 | AFQMC | QQP | noul |
| 意图识别 | MASSIVE（中文部分） | MASSIVE | choice（先切成 ≤ 20 个选项的子集） |

**agent（Agent 场景）**

| 任务 | 来源 | 转成的题型 |
|---|---|---|
| 客服工单分诊 | `scenarios.json` 里的 `support`，用 `distill generate/label --group general` 合成；另可用公开客服数据 | choice、score、noul |
| 提示注入护栏 | `injection` 场景合成；公开 prompt-injection 数据集 | noul、choice |
| 工具路由 | `toolroute` 场景合成 | choice、noul |
| 论文分诊 | `paper` 场景合成 | choice、score、noul |

agent 池可以**完全复用现有的 distill 流水线**，只需把 `--group` 从 `pol2` 换成 `general`。

注意：官方 README 写明 AG News 和 BoolQ 在官方的训练混合里。所以通用考卷在这两个数据集上的分数，对官方模型会偏高，报告时要单独标出来。

### 3.3 PoL2 数据 v2（沿用 v1 流水线，重点改进）

1. 另外生成约 600 条谄媚样本，**只用于训练**。`sycophantic` 和 `reply_type` 直接使用**构造标签**（由主张真假和回复类型推出），并给正例加权，目标是正例比例达到 25–35%。
2. 改写 `eap.honest` 和 `lovelang.truthful` 的题目说明，把"说真话"和"说得好听"拆开（v1 中这两题的老师分歧率分别是 32% 和 22%）。
3. 生成模型和老师模型继续分开（gemma4 负责生成；Jev、qwen、llama 负责打标签，有 Spark 时加一个更大的老师）。
4. 目标规模：第一阶段约 **10,000 道题**，第二阶段约 30,000 道题。

### 3.4 反捷径对照题（neighbor 池里最重要的一类）

专门造一类**表面像 PoL2、答案却不同**的文本，打掉模型的表面捷径：

- 满是"爱""关心""为你好"字眼，实际上是在施压操纵 → `eap.manipulative = true`
- 措辞很冲，但说的是真话，而且尊重对方 → `lovelang.stance = love_language`
- 附和的是一个**正确**的主张 → `syco.sycophantic = false`

这类题数量不需要多（约占 neighbor 池的 10%），但每一类都要有。

### 3.5 统一格式

所有数据池使用和现有 `train.jsonl` 相同的格式，只新增一个 `pool` 字段：

```json
{"id": "...", "pool": "general", "workflow": "ocnli", "group_id": "...", "source": "public:OCNLI",
 "state": "...", "questions": "{...}", "gold": "{...}"}
```

- 公开数据集的 gold 是**硬标签**，写成 one-hot 分布，再做 ε = 0.02 平滑（和老师标签的处理一致）。
- 同一个任务的**题目说明要准备 3–5 种写法**，中英文都有，每条随机选一种，避免模型死记题干字符串。

### 3.6 切分

- 每个数据池分别按 `group_id` 切成 train / calib / test，比例约 80 / 5 / 15。
- 公开数据集如果有官方测试集，优先用官方测试集当 test，**不参与训练**。
- 训练集和测试集之间做文本去重（完全相同的，以及归一化后相同的）。
- PoL2 的 test 继续沿用 v1 的留出组，保证 v1 和 v2 的结果可以直接对比。

### 3.7 混合抽样规则

1. **每个 epoch 重新抽样**：按 3.1 的比例从各个池里抽题。
2. **总量上限**：每个 epoch 的总题数 ≤ PoL2 训练题数 ÷ 10%（再乘以允许的重复次数）。
3. **重复上限**：整个训练过程中，同一道题出现的次数 ≤ 4。PoL2 数据不够的时候，**缩小总量**，而不是让 PoL2 题反复出现。
4. 池内再按 workflow 均衡抽样，防止某个大数据集（比如 MNLI）挤占其他任务。

规模对照（估计，按 75 题/秒、3–4 个 epoch 计，文本长的话要乘 3–5）：

| PoL2 训练题数 | 每个 epoch 总题数 | 其中非 PoL2 | 5070 单次训练时间 |
|---:|---:|---:|---:|
| 3,200（v1 现状） | 32,000 | 28,800 | 约 0.5 小时 |
| 10,000（v2 第一阶段） | 100,000 | 90,000 | 约 1.5–4 小时 |
| 30,000（v2 第二阶段） | 300,000 | 270,000 | 约 5–15 小时 |

## 4. 训练方案

### 4.1 路线 1：从官方 `laya-multilingual` 继续训练（先做）

- 起点：`convaiinnovations/laya`，子目录 `multilingual`
- 数据：3.7 节的混合数据
- 超参数（沿用 v1）：`lr_encoder = 2.5e-5`，`lr_head = 1e-4`，micro-batch 8 × 累积 8（有效 batch 64），3–4 个 epoch，bf16，开启梯度检查点，`max_len = 1024`，`head_max_len = 256`
- 适用场景：主力方案，成本最低

### 4.2 路线 2：从编码器重建 Laya（对照）

- 起点：`jhu-clsp/mmBERT-base` 编码器，**决策头随机初始化**（`build_model(cfg, pretrained=True)`，不加载官方的 `model.safetensors`）
- 数据：和路线 1 **完全相同**，这样两条路线的差异只来自起点
- 超参数：决策头是新的，建议 `lr_head = 3e-4`，`lr_encoder = 3e-5`，前 5% 的步数做 warmup，其余参数同路线 1
- 目的：回答"不依赖官方 checkpoint，自己训出来的效果能不能更好"。**只有路线 2 在两张卷上都明显优于路线 1，才值得切换过去。**

### 4.3 校准

- 每种题型拟合一个温度（与官方做法一致）。校准集按数据池比例从各池的 calib 部分抽取。
- 评估时 **PoL2 和通用分开报告 ECE**。如果 PoL2 的 ECE 明显偏高，再考虑单独为 PoL2 场景拟合温度（需要改 laya 的运行时配置，另行评估）。

### 4.4 需要开发的代码

| 模块 | 内容 |
|---|---|
| `distill/general/` | 每个公开数据集一个转换器：原始数据 → 统一格式（`pool`、多种题干写法、ε 平滑） |
| `distill mix` 命令 | 按比例抽样和重复上限，生成每个 epoch 的题目清单；输出配比报告（池、语言、题型） |
| `distill/train.py` | `--from-encoder`（路线 2）、`--mix` 配置文件、每个 epoch 重新抽样、学习率 warmup |
| `distill/evaluate.py` | 按 `pool` 和 `workflow` 分组报告；读取通用考卷 |
| 比例对比实验脚本 | 一条命令跑完 0/5/10/20/100% 五组训练和评估，输出汇总表和曲线 |
| `tests/` | 用小的假数据跑通转换、混合、训练冒烟测试（CPU 即可） |

## 5. 硬件分工

| 任务 | RTX 5070（12 GB） | DGX Spark（128 GB） |
|---|---|---|
| Laya 训练和评估（base 级编码器，1024 长度） | **主力**，带宽高，速度更快 | 可以做，但不会更快 |
| 长上下文（4k–8k）训练 | 显存不够 | 可以 |
| 老师打标签 | 7–8B 模型；建议从 Ollama 换成 vLLM 批量推理（估计能快约 10 倍） | 70–120B 级别的老师，标签质量更高 |
| 公开数据转换 | 任意机器都行 | 任意机器都行 |

没有 Spark 的话，整个方案也能完成，只是老师质量的上限低一些。

## 6. 评估方案

### 6.1 PoL2 考卷（已有）

老师共识 test、独立裁判（gemma4:26b）、构造 gold（全新谄媚样本）、人工金标集。指标包括准确率、Brier、ECE、score MAE，以及不变性诊断（归属效应、A/B 互换一致率）。

### 6.2 通用考卷（新建）

- 从 3.2 节的每个 neighbor / general / agent 数据集的 test 部分，各抽 300–500 题（固定随机种子，**只建一次，之后不再改**）。
- 报告：每个数据集的准确率和 ECE、各池的宏平均，以及和多数类基线的对比。
- 参照对象：官方 `english`、`multilingual`、`typed-decisions` 三个 checkpoint，以及 v1 学生。

### 6.3 比例对比实验

- 固定每个 epoch 的总题数和训练步数，只改变 PoL2 的占比：**0% / 5% / 10% / 20% / 100%**（100% 相当于 v1 的做法）。
- 每一组都考两张卷，画出"PoL2 成绩 – 通用成绩"曲线。
- 预期结果：0% 时通用最好、PoL2 最差；100% 时正好相反；中间某处两边都不错。**实际的最佳点由这个实验决定**，10% 是默认值。

## 7. 实验清单与执行顺序

| 编号 | 内容 | 机器 | 耗时（估计） | 完成后回答的问题 |
|---|---|---|---|---|
| **E0** | 建通用考卷；考官方三个 checkpoint 和 v1 学生 | 5070 | 2–3 天 | v1 学生（100% PoL2）偏科了多少？ |
| **E1** | PoL2 数据 v2（3.3、3.4 节） | 5070 / Spark | 1–2 周 | 谄媚正例够不够，题目说明的歧义有没有降低 |
| **E2** | 通用数据池（约 9 万题），与 E1 并行 | 任意 | 约 1 周 | — |
| **E3** | 路线 1，10% 混合 | 5070 | 半天 | 混合训练能否同时过两张卷 |
| **E4** | 比例对比实验（路线 1） | 5070 | 1–2 天 | 10% 这个上限合不合适 |
| **E5** | 路线 2，采用 E4 选出的比例 | 5070 | 1 天 | 从头重建值不值得 |
| **E6** | 扩大到约 30 万题（可选） | 5070 | 2–3 天 | 规模加大还有没有收益 |

**决策点**：
- E0 之后：如果 v1 学生的通用能力几乎没有退步，就向师兄报告这个结果，但仍然按混合方案执行，因为 E4 会给出更完整的答案。
- E3 之后：如果 PoL2 成绩明显低于 v1，先查数据问题（PoL2 题数、重复次数、题干写法），不要急着调高 PoL2 比例。
- E5 之后：路线 2 不比路线 1 好，就停在路线 1。

每个实验都要写一份 `docs/findings/<日期>_<名字>.md`，格式参照 v1：诚实条款、做了什么、三种参照下的结果、负结果、下一步。

## 9. 风险与诚实条款

1. **学生的上限是老师。** PoL2 的 gold 是老师共识，不是真值。只有人工金标集能回答"判得对不对"。
2. **合成文本的风格偏差。** PoL2 全部由 gemma4 生成，在真实文本上的表现未知。有条件的话，要收集少量真实、已脱敏的文本做测试（不进训练）。
3. **公开数据集的许可。** 未来如果有商用打算，学术许可的数据集必须替换。
4. **Jev 的使用条款。** 用 Jev 的输出训练其他模型之前，要先确认条款允许。
5. **10% 是经验值。** 以 E4 的结果为准，不作为教条。
6. **单一温度的局限。** 一种题型只有一个温度，可能照顾不到所有数据池，所以 ECE 要分池报告。
7. **负结果照样记录。** 包括路线 2 没有优于路线 1、混合训练降低了 PoL2 成绩等。

## 10. 待确认的问题
